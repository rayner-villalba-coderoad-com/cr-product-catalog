# Quickstart Validation Guide: Clothing Brand Product Catalog

**Feature**: `001-clothing-catalog`
**Date**: 2026-06-24

This guide describes how to run and manually validate the catalog once implementation
is complete. It is not an implementation guide — see [plan.md](./plan.md) and the
tasks generated by `/speckit-tasks` for that.

---

## Prerequisites

- Node.js 18.17+ installed
- A package manager: `npm`, `pnpm`, or `yarn`
- The project bootstrapped with `create-next-app` (TypeScript + Tailwind + App Router)

---

## Setup

```bash
# 1. Install dependencies
npm install

# 2. Verify TypeScript compiles with zero errors (strict mode)
npx tsc --noEmit

# 3. Verify linting passes
npm run lint

# 4. Start the development server
npm run dev
```

Open `http://localhost:3000` in a browser — it should redirect to
`http://localhost:3000/products`.

---

## Validation Scenarios

### Scenario 1 — Product Grid renders (US1 / FR-001, FR-002)

1. Navigate to `http://localhost:3000/products`.
2. **Expected**: All mock products appear in a grid layout. Each card shows an
   image, name, price, and a "View Details" button.
3. Resize the browser window to < 640 px (mobile) — cards MUST stack in a single
   column with no horizontal overflow.
4. Resize to ≥ 1024 px (desktop) — cards MUST appear in at least 3 columns.

**Pass criteria**: Every product from the mock dataset is visible; layout reflowing
works at all three breakpoints; no console errors.

---

### Scenario 2 — Category filter (US2 / FR-003, FR-005, FR-006)

1. On `/products`, select "Tops" from the category filter.
2. **Expected**: Only products with `category === 'Tops'` are displayed. All others
   disappear from the grid — no page reload.
3. Select "Bottoms".
4. **Expected**: Grid updates to show only Bottom products.
5. Select a category with no matching products (if applicable) or use "All" to
   reset.
6. **Expected**: Either the `<EmptyState>` message appears, or all products return.

**Pass criteria**: Grid updates immediately; correct subset shown per category; empty
state renders instead of a blank grid when no items match.

---

### Scenario 3 — Price sort (US2 / FR-004, FR-005)

1. On `/products` with no category filter, select "Price: Low to High".
2. **Expected**: Products re-order with the lowest-priced item first.
3. Select "Price: High to Low".
4. **Expected**: Order reverses; highest-priced item is first.

**Pass criteria**: Order changes immediately without page reload; prices are in
correct ascending/descending sequence.

---

### Scenario 4 — Product detail page (US3 / FR-007, FR-008, FR-009)

1. Click "View Details" on any product card.
2. **Expected**: Browser navigates to `/products/{id}`.
3. Verify: product name, description, and inventory status badge (In Stock / Low
   Stock) are shown.
4. Click the gallery prev/next buttons (if the product has > 1 image).
5. **Expected**: The displayed image changes; no layout shift occurs.
6. If the product has only one image: verify prev/next buttons are hidden or absent.
7. Select a size and a color.
8. **Expected**: Selected size button and color swatch are visually highlighted.
9. Verify the "Add to Cart" area is rendered and visible.

**Pass criteria**: All detail page elements render; gallery navigation works;
selectors highlight selection; Add to Cart area present.

---

### Scenario 5 — Not found route

1. Navigate directly to `http://localhost:3000/products/does-not-exist`.
2. **Expected**: A "Product not found" message with a link back to `/products` is
   displayed. No error page, no blank screen.

**Pass criteria**: Friendly not-found message renders.

---

### Scenario 6 — Keyboard operability (FR-010 / SC-004)

1. On `/products`, press `Tab` to cycle through all interactive elements.
2. **Expected**: Every filter option, sort option, and "View Details" button receives
   a visible focus ring when focused.
3. With a "View Details" button focused, press `Enter` or `Space`.
4. **Expected**: Browser navigates to the product detail page.
5. On the detail page, `Tab` through gallery controls, size buttons, color swatches,
   and "Add to Cart".
6. **Expected**: All are reachable and activatable by keyboard; no keyboard trap.

**Pass criteria**: Full keyboard navigation without a mouse.

---

### Scenario 7 — No layout shift (FR-011 / SC-003)

1. Open Chrome DevTools → Lighthouse.
2. Run a Lighthouse audit on `/products`.
3. **Expected**: CLS score ≤ 0.1 (green).

**Pass criteria**: Lighthouse CLS passes; no images causing shift during load.
